## Conventions

> Seed entries; expand as code lands.

- **Timestamps**: exchange time (`etime`) only. Other clocks (ingestion, wall) recorded but not used as inputs to features or labels.
- **Time units**: **nanoseconds everywhere** (storage, joins, features, simulator, MLflow) as 64-bit integers since Unix epoch. No mixed-unit math; no implicit truncation. Human-readable rendering is **UTC ISO 8601 form with nanosecond precision and `Z` suffix** — e.g., `2026-05-02T14:30:45.123456789Z`.
- **Symbol naming**: Binance canonical (e.g., `BTCUSDT` for Spot, `BTCUSDT-PERP` or per-API name for Swap). Document the exact mapping per dataset.
- **Currency / units**: prices in quote currency; sizes in base currency; notional in USDT.
- **File layout** (TBD before v0): partition by `symbol/date`, Parquet, schema versioned.
- **Archive unit registry**: `data.binance.vision`'s `(futures-um, trades)` daily/monthly archive convention is `header=yes, time_unit=ms` — a header row `id,price,qty,quote_qty,time,is_buyer_maker` with `time` as a 13-digit millisecond epoch, measured against the real 2026-09-12 daily file (791,576 rows, Phase 3 Plan 01). `mvp/spec/unit_registry.toml` is the machine-readable source of truth this bullet summarizes; code resolves it only through `data/unit_registry.py:get_unit_entry(market, dataset)`, which raises on an unrecognized `(market, dataset)` pair rather than guessing.
- **Time alignment**: feature state accumulates over **every** incoming row (BBO updates, trades, …) — no rows are skipped during ingest, so accumulators (rolling windows, EMAs, OFI, etc.) see the full event stream. **Decision points** (training labels, model inference, simulator order/cancel decisions) are emitted only on the **last row of each `etime`** group — a proxy for "decide at end of received packet, not in the middle of it". When multiple events share an `etime`, the last one (latest in arrival order within the file) is the decision row; preceding rows update state but produce no output. This applies uniformly across Stage 1 (forecast) and Stage 2 (sim).
- **Side conventions**: `tradeSide ∈ {-1, 0, +1}` (sell, unknown, buy). Trade-side backfill rule (applies **only** to legacy rows where the raw side is absent or `0` — see [Trades-backfill side-exactness](#trades-backfill-side-exactness) below; an exact side is never re-classified): closer to bid ⇒ sell; closer to ask ⇒ buy; tie ⇒ 0. Backfilled side stored alongside raw (`tradeSide_raw`, `tradeSide_corrected`).
- **Resync events**: explicitly tagged in the data; downstream features must respect a configurable post-resync warm-up.
- **Tech stack (Python)**: `polars` + `numpy` + `numba` (sim hot path). **No `pandas`** — `polars` is faster on the workloads here and avoids the index/dtype landmines. Transformer track adds PyTorch; tree track adds LightGBM (default), CatBoost or XGBoost optional; regression track stays in scikit-learn. MLflow for tracking. Single feature-pipeline code path shared by training, inference, and simulator (Production–research drift mitigation).

### Spot-L1 clock exception

Spot L1 is deferred post-MVP (swap-only capture, Phase 1 decision). Binance's spot
`bookTicker` stream carries no exchange timestamp field at all — only swap/futures
`bookTicker` carries `E`/`T`. If spot L1 is ever captured, the `etime` approach for it
(e.g. the `@depth@100ms` diff-depth stream, which does carry `E`; an SBE stream; or an
explicitly documented local-recv-clock exception) **must be chosen and written into
this section first**. No spot row may exist anywhere in the pipeline with a null or
locally-sourced `etime` without this section being updated to describe and justify it.

### Trades-backfill side-exactness

- Captured `@trade` stream frames carry `m` (buyer-is-maker) — the side is **exact**,
  not inferred.
- `data.binance.vision` futures `trades` daily dumps carry `is_buyer_maker` — the side
  is **exact**, not inferred.
- Nearest-quote classification (`tradeSide_corrected`; closer to bid ⇒ sell, closer to
  ask ⇒ buy, tie ⇒ unknown) applies **only** to legacy rows where the side field is
  absent or `0`. An exact side (from `m` or `is_buyer_maker`) is never "corrected" by
  the nearest-quote heuristic.
- **Sign convention, pinned**: `m`/`is_buyer_maker = true` ⇒ the buyer was the maker ⇒
  the aggressor **sold** ⇒ `tradeSide = -1`. `m`/`is_buyer_maker = false` ⇒ the
  aggressor **bought** ⇒ `tradeSide = +1`. Asserted by a committed test
  (`tests/ingest/test_trade_side.py`) against real archive rows
  (`tests/fixtures/side_convention_rows.py`, drawn from `BTCUSDT-trades-2026-09-12`)
  — the inverted mapping is the most common Binance sign-convention bug in the wild
  and silently flips the sign of every flow feature.

## Training-data shaping

Two concerns shape what rows enter training: (a) **autocorrelation** between adjacent rows, and (b) **tradeability** of each row given operational latency. Both are deferred at MVP; both become relevant when realism increases. Time alignment (the related decision-row rule) is documented under [Conventions](#conventions).

### Subsampling for autocorrelation

Consecutive rows in a high-frequency time series are heavily autocorrelated. Treating them as i.i.d. inflates effective gradient updates from redundant signal and produces over-confident metrics. Common remedies:

- **Stride subsampling** — keep every k-th row.
- **Event-driven sampling** — keep rows at significant book changes / trade clusters.
- **Bar-based aggregation** — time bars, tick bars, dollar bars.
- **CUSUM / volatility-triggered sampling** — keep rows where state changes meaningfully.

**MVP default.** No subsampling. Rationale: regression and trees tolerate redundant data and may even benefit from it; transformers self-attend over context so the issue is bounded; label density matters for a small initial dataset.

**Trigger to revisit.** Residual autocorrelation (e.g., Ljung–Box) above a declared threshold; metric instability under cross-fold reshuffling; transformer over-fitting attributable to redundant tokens.

### Tradeability filtering

A training row is *non-tradeable* when its alpha cannot be acted on at the decision timestamp:

- The label-defining price move has already happened by the time the model could react (alpha realizes inside the operational latency window).
- The data feed lags reality enough that what was "seen at `t`" was visible to the market well before `t`.

Training on non-tradeable rows teaches patterns the live system cannot exploit; reported skill exceeds deployable skill.

**MVP default.** No tradeability filter. Justified by the zero-latency assumption — under zero latency every row is tradeable by definition.

**When latency is added (post-MVP).** Define the latency-aware tradeable predicate (e.g., "fraction of the label move occurring after `t + latency` ≥ θ"). Rows failing the predicate are dropped or down-weighted. θ is a hyperparameter picked on validation.

## Decision rule (Stage 2)

Corrected pseudocode (SPEC-03) — supersedes the struck block in `mvp.md`'s "Decision
logic (explicit)" section, which multiplied the predicted return by the midprice and
compared that price *change* against a price *level*, producing wrong signs except by
coincidence.

Let `pred_mid = mid * (1 + pred_10s_return)` be the model's predicted midprice ten
seconds ahead, and `X_price = mid * X_bps / 10_000` be the swept threshold `X_bps`
expressed in price units at the current midprice.

- **When flat** (`position == 0`): go long when `pred_mid > best_ask + X_price`; go
  short when `pred_mid < best_bid - X_price`; otherwise stay flat.
- **When positioned**: only the opposite-direction flip is allowed, using the same two
  comparisons — a long position flips to short when `pred_mid < best_bid - X_price`; a
  short position flips to long when `pred_mid > best_ask + X_price`. No same-direction
  or risk-increasing order is ever placed.

This is the authoritative decision rule. Phase 6's oracle tests re-derive Stage-2 P&L
from this exact rule, not from `mvp.md`'s struck pseudocode.

## DOs

- **DO** compute every feature using only data available at or before the decision timestamp; prove it per feature in CI.
- **DO** use rolling / expanding statistics for normalization; never full-period.
- **DO** match the production retrain cadence in walk-forward.
- **DO** apply causal masks in transformers; verify with a leakage test in CI.
- **DO** correct effective sample size for autocorrelation in test statistics (HAC / Newey–West; block bootstrap).
- **DO** version data alongside code; record code hash + data hash + seed + env hash with every run.
- **DO** track the selection-bias budget; record every "look" at any validation segment.
- **DO** re-run the model-class comparison at every realism step (regression, trees, transformer in parallel).
- **DO** keep `spec.md` in sync with code; PRs that touch features/labels must update it.
- **DO** report side-by-side metrics for all three model classes.
- **DO** keep a negative-result log: failed configs are recorded with the same weight as successes, so the same dead-end isn't re-explored under a different name.
- **DO** name every new feature/label uniquely when its definition changes (no silent semantic drift).

## DONTs

- **DON'T** train on data that includes the trade you're predicting from (mid-price recomputed *after* the trade is the classic foot-gun).
- **DON'T** look at the held-out window more than once per gate.
- **DON'T** select features outside the CV fold.
- **DON'T** change the gating metric after seeing results.
- **DON'T** use session-VWAP or forward-looking aggregates without explicit lag.
- **DON'T** treat validation Sharpe as production Sharpe — it has been tuned on.
- **DON'T** treat sparse-trade windows as zero-information without flagging.
- **DON'T** linearly extrapolate from $100 sim positions to predict capacity at scale.
- **DON'T** mix Spot and Swap timestamps without auditing the clock-source difference.
- **DON'T** silently swap data versions between runs — never use `latest` in pipelines.
- **DON'T** ship a more complex model class when the simpler class meets the bar at parity.
- **DON'T** override the critic / red-team / leakage-audit findings without a written rationale on the PR.
- **DON'T** annualize a per-trade Sharpe by `sqrt(trades/year)` — see [Sharpe annualization convention](#sharpe-annualization-convention); the only valid gating Sharpe is the daily-P&L form.
- **DON'T** depend on the full `mlflow` package — it unconditionally imports `pandas` transitively (verified; see `02-RESEARCH.md`); use `mlflow-skinny` + `sqlalchemy` + `alembic` instead.
- **DON'T** call `mlflow.search_runs()` (the pandas-DataFrame-returning convenience API) anywhere in the project, even under `mlflow-skinny` — use `MlflowClient().search_runs()` instead.
- **DON'T** reference `lake/lockbox/` from any agent-run script outside `data/lockbox.py`; gate evaluations are human-invoked only (see `mvp/data/lockbox_POLICY.md`).

## Known HFT/MFT pitfalls

> Each entry: symptoms → mitigations → enforcement point. Update on every encounter.

### Temporal leakage

**Symptoms.** Future info in features (mid computed *including* the predicted trade; session VWAP that closes after `t`; book snapshot exchange-stamped at `t` but observed at `t+δ`); embargo shorter than label horizon → "OOS" overlaps in-sample labels; clock-source mismatch (DST, exchange clock vs. ingestion clock).

**Mitigations.** Per-feature information-set proof; embargo ≥ label horizon (and ≥ feature look-back if it overlaps); documented clock source per dataset; leakage test in CI — shuffling future data must not change feature values.

**Enforcement.** CI test in feature pipeline; manual leakage audit per version, recorded.

### Sample-size illusion

**Symptoms.** Millions of 10s observations look like big data, but autocorrelation collapses effective sample size by orders of magnitude. Naive t-stats and IC significance overstated.

**Mitigations.** HAC standard errors (Newey–West); block bootstrap for confidence intervals; report effective sample size alongside raw count.

**Enforcement.** Reporting template includes effective sample size.

### Label engineering

**Symptoms.** Overlapping forward-window labels → correlated errors → over-confident eval. Mid-price labels for a tradable strategy: high IC ≠ P&L once latency / spread / fees enter. Volatility-dominated MSE: model gets "free" R² fitting volatile periods.

**Mitigations.** Purged k-fold (López de Prado) for inner CV when generating Stage-1 OOF predictions; track **mid-vs-fill skill gap** explicitly (report IC on mid and IC on a fillable proxy); volatility-scaled targets where helpful.

**Enforcement.** Standard reporting includes both mid IC and fillable-proxy IC.

### Data quality

**Symptoms.** Crossed / locked books, exchange outages, stale BBO between updates; sparse-trade windows silently treated as zeros; trade-side classification errors propagating into flow features; snapshot/delta resync gaps; agg-trade aggregation hiding intra-window flow.

**Mitigations.** Sanity filters with audit log (counts of dropped events per filter, per day); explicit sparsity flag feature; trade-side as a feature with its own confidence channel; resync events tagged with a warm-up window after each.

**Enforcement.** Daily data-quality report; any degradation pauses training until acknowledged.

### Distribution shift

**Symptoms.** Crypto regimes (high-vol, trending, range-bound) flip on weekly–monthly scales; funding-rate spikes and liquidation cascades around scheduled events.

**Mitigations.** Regime-split metrics in every report; rolling retrain matched to walk-forward; live calibration monitor (predicted vs. realized return std); automatic demotion if calibration breaks.

**Enforcement.** Calibration monitor wired into the live pipeline (when live exists).

### Multi-testing / selection bias

**Symptoms.** Every feature tried, every hyperparameter, every model class is a "look". 100 features × 10 hp variants × 3 classes = thousands of false-positive opportunities.

**Mitigations.** Declared selection-bias budget per project / per validation segment; lockbox held-out (touched once per gate; a second look invalidates it and forces a fresh window); negative-result log so dead-ends aren't silently re-explored.

**Enforcement.** Selection-bias budget tracked in MLflow; held-out access gated by an explicit "I am about to spend my one look" annotation in MLflow.

### Forecast-vs-execution gap

**Symptoms.** A predictor with strong IC under zero-latency may have negative P&L under realistic latency because alpha realizes inside the latency window. Adverse selection at TOB: getting filled means someone better-informed wanted the trade.

**Mitigations.** Stage-2 simulator owns execution from day 1; fast-alpha-decay curve reported per signal; adverse-selection patterns flagged in trade log (e.g., immediate-after-fill price reversion histogram).

**Enforcement.** Standard report includes alpha-decay curve.

### Production–research drift

**Symptoms.** Feature pipeline that differs between training and live inference; retrain cadence in prod ≠ cadence assumed in walk-forward.

**Mitigations.** Single feature-pipeline code path for both; walk-forward simulates the production schedule exactly.

**Enforcement.** Integration test — same input bytes → same feature values from train and inference paths.

### Capacity / market impact

**Symptoms.** $100 fills are non-impacting; real positions move the book.

**Mitigations.** Never extrapolate linearly from MVP-size results; capacity is its own R&D track (R1/R2).

**Enforcement.** Capacity-claim guardrail in reports — any "expected at size X" claim must cite a source experiment, not extrapolation.

### Monetization specifics

**Symptoms.** High Sharpe paired with extreme turnover — tiny fees demolish edge. Knife-edge X — small parameter drift kills the strategy; doesn't survive walk-forward.

**Mitigations.** Turnover budget enforced in policy; reject knife-edge optima (require a robust region around the maximum, e.g., metric within 90% of peak across an X-band of declared width).

**Enforcement.** Stage-2 hyperparameter selection rejects knife-edge configurations automatically.

### Operational reproducibility

**Symptoms.** Data version drift between runs ("latest" silently changes); random seeds unfixed; run logs not durable.

**Mitigations.** Run manifest in MLflow includes code hash, data hash, seed, env hash; immutable run logs; `latest` never used in pipelines.

**Enforcement.** CI rejects pipelines that resolve `latest` at runtime.

## Sharpe annualization convention

- **Headline annualized Sharpe** = `mean(daily_pnl) / std(daily_pnl) * sqrt(365)`,
  computed on UTC-day P&L extracted from the simulator's equity curve (crypto perps
  trade 24/7 — 365, not 252, trading days/year).
- Daily P&L is the sum of realized + mark-to-market P&L over each UTC day. A day with
  zero trades is a valid observation with P&L equal to 0 — it is never dropped or
  imputed.
- **Hourly Sharpe** (`* sqrt(8760)`) may be reported alongside, always explicitly
  labeled "secondary — data-starved diagnostic". It is never the gate.
- The MVP gate ("Sharpe > 5") is evaluated **only** when the held-out window has **at
  least 30 daily observations**. Fewer observations yields the result "insufficient
  history", not a pass/fail verdict.
- **Forbidden**: annualizing a per-trade Sharpe by `sqrt(trades/year)`. This form
  inflates HFT-style Sharpe into meaninglessness and must never be reported as the
  gating metric (see DONTs).

## MLflow tag schema

- Every MLflow run carries exactly these eight mandatory tags:
  `code_hash`, `data_hash`, `seed`, `env_hash`, `segment_manifest_id`, `model_class`, `fold_config`, `stage`.
- `code_hash` — git `HEAD` SHA, with a `-dirty` suffix appended when the working tree
  is not clean at run start.
- `data_hash` — content hash of the dataset manifest the run consumes, or the literal
  string `"none"` for a run that consumes no dataset.
- `seed` — the integer random seed.
- `env_hash` — SHA-256 of `mvp/uv.lock`.
- `segment_manifest_id`, `model_class`, `fold_config`, `stage` — may be the literal
  string `"n/a"` before their owning phase lands, but the **keys must always be
  present**; a tag dict missing any key is a schema violation, not an optional field.
- The tracking wrapper (`mvp/tracking/mlflow_utils.py`, Plan 03) is the only place a
  run is started; it **rejects** any `start_run` call whose tag dict is missing a
  mandatory key, rather than silently logging a partial tag set.

## Numba no-globals rule

- `@njit`-decorated functions take **every** input as an explicit parameter.
  Module-level globals are limited to compile-time constants declared with an
  explicit UPPER_CASE name (the `Final`/constant escape hatch).
- A `@njit` function that reads a module-level, non-constant global freezes that
  value at first compile — later edits to the global are **silently ignored**, not
  picked up on the next call. This is a correctness trap, not a style preference.
- Enforced by `mvp/tools/check_numba_globals.py` (Plan 02), an AST check that fails on
  any `Name` load inside an `@njit`-decorated function body that resolves to a
  module-level, non-UPPER_CASE binding. The check must run in CI even against zero
  `@njit` functions (none exist yet, Phase 2), so it is proven wired before Phase 4
  adds the first kernel.

## Glossary

> Add terms as they enter the project's working vocabulary.

- **BBO** — Best Bid and Offer (top-of-book, L1).
- **Embargo** — gap between consecutive folds (or between train and validation) preventing temporal leakage of features whose look-back, or labels whose forward-window, would otherwise overlap.
- **etime** — exchange timestamp.
- **HAC** — heteroskedasticity- and autocorrelation-consistent (standard errors). Newey–West is one estimator.
- **Held-out** — quarantined OOS window, looked at once per gate; never tuned on.
- **IC** — information coefficient: rank correlation between predicted and realized returns. Primary Stage-1 metric at horizon `h`.
- **L1 / L2 / L3** — top-of-book / aggregated depth / full order-by-order book respectively.
- **OOF** — out-of-fold predictions: predictions on a sub-block produced by a model trained on the other sub-blocks; standard ML stacking trick to feed a meta-learner without in-sample leakage.
- **OOS** — out-of-sample (any data not used for training; superset of held-out).
- **Selection-bias budget** — a tracked count of "looks" at validation data; once exhausted, a new validation window is required.
- **TOB** — top of book (synonym of BBO).
- **Walk-forward** — eval that simulates the production retrain schedule by sliding train/val windows forward through time.
