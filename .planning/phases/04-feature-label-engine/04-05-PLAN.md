<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestration order -> disk | Every gate is only as good as its position relative to the first write |
| feature partition -> DQ report -> loader | A day that produces no report row is unloadable; a report regen that drops rows is a silent outage |
| this plan -> the live capture daemon | A build that touched `capture/` could corrupt irreplaceable data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-04-20 | Information disclosure | refusal-after-write ordering | mitigate | Gates 1-2 run before any load or write; the test asserts the directory's absence after each refusal, not merely the exception |
| T-04-21 | Tampering | in-place rebuild of a feature partition | mitigate | Inherited write-once refusal at both the partition path and `issue_manifest`; a real rebuild attempt is observed refusing |
| T-04-22 | Denial of service | the live capture daemon | mitigate | `capture/` is never opened by the build (gaps come from the lake); `ps -p 72546` recorded before and after; no signal is ever sent |
| T-04-23 | Repudiation | a degraded day waved through by widening a threshold | mitigate | Acknowledgement JSON naming every finding, root cause, who and when -- git-committed, validated by `validate_dq_acknowledgement` |
| T-04-24 | Tampering | DQ report regeneration dropping curated verdicts | mitigate | Post-regen check that pre-existing `trade`/`bookTicker` rows retain their verdicts |
</threat_model>
