Create `mvp/features/normalize.py`.

Pin the semantics in the module docstring, because "expanding-window z-score, parameters computed on the training segment only and stored" (D-04-06) leaves one question open and this is the answer:
- WITHIN the training segment, the normalized value at row `t` uses the expanding statistics over training rows `<= t` (strictly causal, including `t` itself -- using row `t`'s own value is not lookahead).
- OUTSIDE the training segment -- validation, inference, the simulator -- the parameters are FROZEN at the training segment's terminal statistics, loaded from the artifact. Nothing downstream ever recomputes from the data it is scoring.
- The artifact therefore stores Welford's `(count, mean, M2)` per feature, not just `(mean, std)`: it is sufficient both to freeze and to resume the expanding path deterministically if a later fold extends the training segment, and it makes the fit auditable.

- `fit_normalization(values: dict[str, np.ndarray]) -> dict[str, tuple[int, float, float]]` -- Welford over the decision-row order (deterministic because the row order is pinned by the partition). Null/NaN rows are EXCLUDED from the fit and their exclusion count is recorded; a feature whose training-segment variance is 0 raises `ZeroVarianceError` naming it rather than dividing by zero.
- `expanding_z(values: np.ndarray) -> np.ndarray` -- the causal within-training transform.
- `apply_normalization(values, params) -> np.ndarray` -- the frozen transform.
- `write_normalization_artifact(params, *, symbol, train_end_date, source_feature_manifest_ids, train_row_count, train_etime_range, lake_root, registry_root, code_hash) -> dict` -- writes one small Parquet (one row per feature: name, count, mean, M2, std, excluded_nulls) under `lake/features_norm/symbol=<symbol>/train_end=<date>/part-<ns>.parquet`, then `store.issue_manifest(dataset=f"{symbol}.features_norm", stream="features_norm", tier=FEATURES_NORM_TIER, dates=[], ...)` -- passing `dates=[]` explicitly so no by-date pointer is attempted for a tier that is addressed by manifest id only. `inputs[]` names the feature manifests the fit consumed, with their sha256s, so provenance stays a chain: curated -> features -> normalization -> run.
- `load_normalization(manifest_id, dataset, *, registry_root, lake_root)` -- `resolve_manifest(expected_tier=FEATURES_NORM_TIER)` + `read_verified_partitions`. Deliberately does NOT call `_enforce_dq_pause`: the artifact tier produces no DQ report rows, and the pause gate treats "no rows for this manifest" as `missing`, which would pause it permanently. Say that in the docstring so nobody "fixes" it by adding the call.

- `compute_decision_rows(events, *, state=None, normalization=None, labels=False) -> tuple[pl.DataFrame, KernelState]` -- runs the merge-side helpers, the kernel, decision-row selection, optionally labels and optionally the frozen normalization, and returns the frame plus the carried-out state.
