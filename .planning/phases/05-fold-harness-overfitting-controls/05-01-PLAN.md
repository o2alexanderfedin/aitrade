<objective>
Build the thinnest real, end-to-end slice of the fold harness: declare a 5-segment layout, issue
its manifest as content-addressed data, materialize one train frame and one val frame through the
harness's own accessor, and see the val materialization counted as a look in MLflow. Per MVP mode,
this is the FIRST non-test slice -- everything after it (P2-P7) refines this path (refusals,
k-fold OOF, budget exhaustion, negative log, admission policy, errata, declaration tool, tripwire,
spec), never restarts it.

The manifest schema is written complete from day one (interface-first): every D-05-09 field exists
in this plan's `issue_segment_manifest`, even where the VALUE is an honest placeholder --
`admission_policy={"stale_book_threshold_s": None}` (None means "exclude nothing," a real, legal
policy value, not a stub) and `errata_id=None` ("no errata computed for this manifest yet," also a
real, honest value). Both are REPLACED with real computed values by a later manifest (P4/P7) --
manifests are write-once, so "replaced" means a NEW id, never an edit.

Purpose: prove the shape end to end on synthetic data before any refinement plan builds on it, and
give every later plan (P2-P7) a concrete, working `materialize`/`issue_segment_manifest`/`budget`
surface to extend rather than design from scratch.
Output: `mvp/harness/` as a real, importable package with four modules and a passing integration
test that proves the walking-skeleton path.

| Boundary | Description |
|----------|-------------|

| `budget.record_look` -> MLflow SQLite store | The durable counter; a reset or unreachable store must never read as "zero looks spent" |
