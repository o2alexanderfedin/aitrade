<objective>
Close the loop between budget and segment issuance (D-05-14) and ship the negative-result log
(D-05-22, EVAL-04).

Plan-checker iteration 1 blocker 4 changes the shape of the fix from this plan's original design:
the issuance-time overlap refusal is now UNCONDITIONAL, not opt-in. `issue_segment_manifest` gains a
REQUIRED `tracking_root` keyword argument and self-discovers every existing manifest under
`registry_root/segments/` by globbing -- there is no `existing_manifests` parameter a caller could
omit to skip the check. This is a signature change to a function P1 and P2 already established and
tested; this plan updates those existing call sites (in `test_segments.py`, already in this plan's
`files_modified`) rather than leaving them broken.

Purpose: D-05-14 is a hard leakage-adjacent control (a re-used, already-exhausted validation window
is exactly the multi-testing risk the budget exists to prevent) -- an opt-in check that a caller can
skip by omitting two keyword arguments is not the same guarantee, and the checker's decision removes
that gap.
Output: `harness/budget.py` gains exhaustion; `harness/segments.py`'s `issue_segment_manifest` gains
mandatory self-discovery and overlap refusal; `harness/negative_log.py` and its CLI are new.
</objective>
