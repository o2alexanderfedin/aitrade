**The four trainers** (D-07-08, in this order), each a small class satisfying `Trainer`, each constructed with its hyperparameters and each reporting them through the `hyperparameters` property so `predictor_id` can hash them:
1. `LinearRegression` — the honest floor. No `random_state` parameter exists on it.
2. `Ridge` — `solver="auto"`, which resolves to `cholesky` on dense input (`A = X.T @ X`; `A.flat[::p+1] += alpha`; `scipy.linalg.solve(A, Xy, assume_a="pos")`). Deterministic; `random_state` is used only by `sag`/`saga`. Pass a seed anyway so the MLflow `seed` tag is real.
3. `ElasticNet` — `selection="cyclic"` (deterministic by iteration order) and an explicit `random_state`. Fix `max_iter` and `tol` as declared hyperparameters so a convergence warning is a config property, not an accident.
4. `Ridge` on `PolynomialFeatures(degree=2, include_bias=False)` — FCST-01's "small non-linear" member, kept inside scikit-learn so trees stay Phase 8's territory. **Its `hyperparameters` are `{"alpha": a, "degree": 2}`, not `{"alpha": a}`** — see the collision note under the grid. **Assert the expansion is exactly 9 columns** (3 linear + 3 squared + 3 cross: `(x0, x1, x2, x0*x0, x0*x1, x0*x2, x1*x1, x1*x2, x2*x2)`) and raise naming both counts otherwise. Measured: exactly 9 for 3 inputs, not 6 and not 10. This count is the only one of D-07-23's three refusals that can catch a price column entering through an interaction term.

**The grid — fixed, hand-written, COUNTED. No Optuna (Phase 8 owns FCST-05).** Use exactly this, exported as a module-level tuple whose length is the `n_configs` the run logs:

      Ridge + poly2    alpha in {1e-3, 1.0, 100.0}         3  configs

**`degree` must be inside the poly2 trainer's `hyperparameters`, and this is not cosmetic.** Ridge and Ridge+poly2 share three alpha values (1e-3, 1.0, 100.0) at an identical `model_class`, seed, code hash and normalisation id. `predictor_id` hashes exactly D-07-14's five fields, so without `degree` in the mapping those three pairs would produce IDENTICAL `predictor_id`s: the negative-result log would deduplicate away up to three distinct ineligible configs (falsifying D-07-20), and a stored table's `predictor=<first 16 chars>` directory would name a config that never produced it. With `degree` in the mapping, `design` DERIVES from the recipe instead of shadowing it.

Small alphas are safe here and that is measured, not assumed: the raw three-feature Gram has condition number 712, and after the FEAT-05 z-score it is 1.28, so the "never use normal equations" objection does not bite (it would if `mid` were in the matrix — one more reason D-07-09 excludes it).
