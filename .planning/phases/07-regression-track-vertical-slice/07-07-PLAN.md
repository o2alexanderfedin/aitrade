`forecast_metrics(pred, y, *, train_mean: float) -> dict` — **`train_mean` is a REQUIRED keyword with no default.** The zero-skill control column is "a constant predictor at the TRAIN mean", and the only mean available inside a scoring function is the evaluation set's own. Logging that under a key saying "train" would substitute a different, weaker statistic for the one the human checkpoint in plan 07-11 asks the developer to read, and `mode="val"` never reads the train frame at all. The value comes from `FrozenLinearPredictor.train_target_mean`, which the fit captured and the body carries. Returns, on the SCORABLE row set (`np.isfinite(pred) & np.isfinite(y)`, one row set shared by every statistic in the dict):
- `n_scorable`
- `r2_vs_zero = 1 - SSE / sum(y**2)` — the constant-ZERO predictor as reference, the one D-07-18 names
- `r2_vs_mean = 1 - SSE / sum((y - y.mean())**2)` — the ordinary R^2. They differ by exactly `n * y_mean^2`; measured in-sample on 2026-09-18, `SS_mean / SS_zero = 0.9983534`, and an OLS scored +0.022238 versus +0.020625, a 7.8% relative gap.
- `rank_ic_all` and `rank_ic_non_tied` — `spearmanr(...).statistic`, the second on `y != 0.0`. `spearmanr` is `rankdata` (average ranks) then ordinary Pearson; there is no separate tie-correction term, and Pearson-on-ranks is correct under ties unlike the `6*sum(d^2)/(n(n^2-1))` shortcut.
- `tie_fraction = (y == 0.0).mean()` — exact equality is correct: these are genuine exact zeros from an unchanged mid, and day 18's scorable rows hold only 65,888 distinct target values among 7.85M rows.
- `r2_vs_zero_of_constant_train_mean` — computed as `1 - sum((y - train_mean)**2) / sum(y**2)` with the passed-in TRAIN mean, never with `pred.mean()` or `y.mean()`. This is the zero-skill control column that makes the loophole visible rather than latent. Measured out of sample, the constant-at-train-mean predictor scores near noise (-0.000070, +0.000012, -0.000029, -0.000007 on four train-internal splits); in sample it scored +0.001647, which is why the control is reported rather than assumed harmless.

Catch `scipy.stats.ConstantInputWarning` with `warnings.catch_warnings()` + `simplefilter("error", ...)` and return `float("nan")` for that IC. `spearmanr` returns NaN for a constant input; `np.nan > 0` is `False`, so a naive comparison fails closed but reports "IC not positive" when the truth is "the prediction has no ordering at all". The gate detects it separately.

Docstring must state the two corrections to the decisions this implements, because a reader will otherwise re-derive the wrong ones:
- The 43.9% zero point mass is a property of **2026-09-13 alone** (3,012,962 of 6,864,853 rows, verified). The pool is 20.01% and the Option A `val` window is 13.83%. The tie fraction is a PER-SEGMENT quantity; a hardcoded 43.9% would describe a day that is inside `train` (correction C3).
- Ties do not reliably flatter anything. Measured: on day 18 (9.77% ties) including them INFLATES the IC by 1.3%; on day 13 (43.89%) it DEFLATES it by 3.2%. The two statistics answer different questions — can the model order the whole population, versus can it order the rows whose target actually moved — and the second is what a threshold-crossing policy monetises. Report both; present neither as a correction of the other (correction C2).
