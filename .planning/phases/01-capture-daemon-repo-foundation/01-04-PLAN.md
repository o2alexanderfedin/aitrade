## Phase Goal

> Same discrepancy noted in Plan 01: ROADMAP.md's Phase 1 goal is not user-story format. Not
> reinvented here; see Plan 01's `## Phase Goal` section for the full note.

Redundant capture daemon records history continuously; gap ledger records every capture outage;
liveness watchdog flags stalls — this plan closes the "liveness watchdog flags stalls" clause that
Plans 02-03's reactive gap detection cannot cover on its own (a stream that never resumes has no
next message to trigger a reactive check), and hardens the write path with a chaos test proving
the atomicity claim already built in Plan 02.

<objective>
Add the proactive liveness watchdog (periodic stall alarm + continuous free-space monitoring),
prove the atomic-write claim under a simulated crash, and produce the deploy artifacts (Dockerfile,
systemd unit) that make relocating capture to an always-on VPS a config change, not a rewrite —
closing out Phase 1's remaining success criteria.

Purpose: Plan 03's gap detection is reactive (fires only when a new message resumes the flow);
total, permanent silence on a stream needs an independent periodic check, which is this plan's
job. This is also the natural point to prove the Plan 02 atomic-write claim under an actual
simulated crash, rather than leaving it as an unverified design assertion.
Output: `mvp/data/capture/watchdog.py`, `mvp/deploy/{Dockerfile,capture.service}`, hardening tests,
and a final human confirmation that the full Phase 1 daemon (redundant, watchdogged, deploy-ready)
is running.
</objective>
