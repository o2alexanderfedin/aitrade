  <behavior>
    latest-ban (`check_latest_ban.py`):
    - `scan_source(source, filename)` walks `ast.Call` nodes whose function resolves to a path-construction call (`pathlib.Path(...)`, `open(...)`, or an f-string / `str.format` building a path — detect via `ast.JoinedStr` and `ast.Constant` string arguments to ANY call, not only a fixed allowlist of function names, since the ban's job is catching path segments not naming every possible constructor) and, within their string/`JoinedStr` constant arguments, applies the regex `(^|/)latest(/|$)` to each constant string segment; a match is a `Violation`.
    - A string literal `"data/latest/file.parquet"` passed to `pathlib.Path(...)` is flagged.
    - A string literal `"the latest research shows..."` (prose, no path separator around the word) passed to any call is NOT flagged (the regex requires the word to be its own path segment).
    - `main()` scans only `mvp/data/` and `mvp/pipelines/` (skip `mvp/pipelines/` if it does not yet exist), with the same venv/cache exclusions as Task 1, and the same `scanned {N} files` visibility line.

    numba-no-globals (`check_numba_globals.py`):
    - `is_njit_decorated(fn)` returns True if any decorator's `ast.dump()` contains `"njit"`, or contains both `"jit"` and `"nopython"`.
    - Locals for a given (possibly nested) function are the UNION of: its own parameter names, every `ast.Name` target with `ast.Store` context anywhere in its body (assignment targets), `for`/`with`/comprehension target names, and — recursively — every nested `def`'s own such locals (a nested function's parameters/assignments are never globals relative to the outer njit function).
    - Module-level "global" candidates are `ast.Assign`/`ast.AnnAssign`/`ast.AugAssign` targets at module top level, PLUS any name referenced via an explicit `global` statement inside the function (flagged immediately, regardless of case). `ast.Import`/`ast.ImportFrom` bindings are explicitly exempt (never flagged), matching the documented accepted gap.
    - A `Name` load inside an `@njit` function body that resolves to a module-level candidate, is not in that function's (or an enclosing nesting level's) locals, and is not entirely UPPER_CASE, is a `Violation`.
    - Fixture case: a module with `MAX_POS: int = 100` (uppercase, module-level) and `some_mutable_global = 5` (lowercase, module-level) and one `@njit` function reading both plus doing `total = 0; total += 1` internally (a local, must NOT be flagged) — expected violations: exactly one, naming `some_mutable_global`; `MAX_POS` and `total` never appear in the violation list.
    - `main()` scans `mvp/` recursively (excluding `.venv`/cache dirs) for `@njit`-decorated functions, prints `scanned {N} files, {M} njit functions`, and exits 0 against the current repo (Phase 1 has no `@njit` code yet — `M` is legitimately 0, and that is a passing, visible run, not a silent no-op).
  </behavior>
  <action>
Implement both scripts as separate modules, each with `scan_source`, `Violation`, and `main()` mirroring Task 1's shape (dataclass Violation, `__str__`, exit-code convention, visibility print line). For `check_latest_ban.py`, use `import re` with the compiled pattern `re.compile(r"(^|/)latest(/|$)")`, applied to each `ast.Constant` string and each string-typed constant segment of an `ast.JoinedStr` (walk `node.values`, take `ast.Constant` entries). For `check_numba_globals.py`, implement the local-name collector as a recursive helper that, given a `FunctionDef`/`AsyncFunctionDef` node, returns the union described in the behavior spec — walk `ast.walk(node)` but stop descending into a nested `FunctionDef`'s further-nested defs only for the purpose of not double-counting (simplest correct approach: collect locals per node via a dedicated one-level walk of `node.args.args` plus every `Store`-context `Name`/target found anywhere in `ast.walk(node)`, which correctly captures nested-def locals too since `ast.walk` descends into them — nested-def parameter names are `Store`-context via their own `arg` nodes captured through `node.args.args` at each nesting level encountered during the same top-level `ast.walk`). Handle `ast.Global` nodes explicitly: any name in a `Global` node's `.names` list inside the njit function is an immediate violation with message `"explicit 'global' statement"`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Developer-authored source files -> AST scanners | The scanners trust that source parses as valid Python; a syntactically-broken file is caught by other tooling (ruff/pytest collection), not these scripts |
| mvp/uv.lock on disk -> check_pin_versions.py | Trusts the lockfile as the record of what's actually installed; a manually `pip install`-ed package outside the lock is invisible to this check |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-2-01 | Tampering | mvp/tools/check_catalogue_completeness.py | mitigate | AST scan flags both unknown literal names and non-literal (dynamically constructed) names as violations, closing the obvious "build the string at runtime" bypass at the call-site level |
| T-2-02 | Tampering | mvp/tools/check_latest_ban.py | accept | Scoped regex on string/JoinedStr literals at path-construction call sites catches the literal-`"latest"` case; a determined bypass via runtime string concatenation (`"lat" + "est"`) or a computed "most recent file" path that never spells the word is NOT caught by static analysis — accepted per 02-RESEARCH.md Pitfall 3 and the security_enforcement brief's named honest threat; a runtime symlink-resolution guard is out of scope for Stage 0 and deferred to Phase 3's data-loader work if it proves necessary |
| T-2-03 | Tampering | mvp/tools/check_numba_globals.py | mitigate | AST scan flags module-level non-constant reads inside @njit bodies, including via explicit `global` statements; imported-name mutation (e.g. a module-level `from x import TABLE` where `TABLE` is later mutated in place) is a known, documented residual gap (02-RESEARCH.md Architecture Patterns > Pattern 4) — accepted for Stage 0 since no such import pattern exists yet in the repo |
| T-2-07 | Tampering | mvp/tools/check_pin_versions.py | accept | A developer running `pip install` directly into the venv (bypassing `uv add`) is invisible to a lockfile-content check; accepted because Phase 1 already established `uv`-only environment management as the project convention (uv.lock is the source of truth) and this is a single-developer research repo, not a multi-contributor supply chain |
</threat_model>
